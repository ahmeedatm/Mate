# Trackpad — plan de développement

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal :** l'écran de la tablette devient le pavé tactile de l'ordinateur.
**Spec :** [docs/superpowers/specs/2026-10-28-trackpad-design.md](../specs/2026-10-28-trackpad-design.md)

## Global Constraints

- Branche locale `feat/trackpad`. Les agents ne commitent pas, n'indexent pas, ne poussent pas.
- Contrat : UDP `UNOWHY-POINTER\n<jeton>\n<seq>\n<json>` (`{"dx","dy"}` ou `{"sx","sy"}`, entiers) sur le port du
  compagnon ; HTTP `POST /pointer/move {dx,dy}`, `POST /pointer/scroll {sx,sy}`, `POST /pointer/button
  {button:"left"|"right", action:"click"|"down"|"up"}` → `{ok:true}`. Bornes |d| ≤ 2000, |s| ≤ 50 ; ≤ 200 paquets/s
  par source ; `seq` croissant par source ; jeton comparé à temps constant ; rien du contenu dans les journaux.
- `os.ts` seul accès système : `pointerMove(dx,dy)`, `pointerScroll(sx,sy)`, `pointerButton(button, action)` ; mêmes
  exports dans `test/fake-os.ts` ; hors Mac/Windows 501.
- Windows : opération `pointer` du pilote (`SendInput`), pilote recompilé avec le SDK de `backend/global.json`
  (`npm run build:helper`, SDK local `%USERPROFILE%\.dotnet-companion`). Ne jamais arrêter/démarrer le service du
  compagnon depuis un agent (le contrôleur le relance depuis le terminal de Bruno).
- Mac : processus JXA résident, écrit sans pouvoir être testé.
- Tablette : envoi regroupé toutes les 16 ms ; accélération sur la tablette ; Cadran ; pas de nouvelle dépendance ;
  textes dans `strings.xml`.
- Gradle : `export TEMP='C:\gtmp' TMP='C:\gtmp' JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"`.
- Backend : 8 tests échouent déjà sur ce PC Windows ; aucun nouvel échec ; prettier par fichier `--end-of-line auto`.

### Task 1 : compagnon — paquets UDP, routes HTTP, `os.ts`, Mac, faux système, tests, sanity
`backend/src/pointer.ts` (pur : `parsePointerPacket(buf, token)`, état `seq`/débit par source, bornes), branchement
dans le socket UDP de `pairing.ts` (messages commençant par `UNOWHY-POINTER\n`, le reste inchangé), routes dans
`routes/` (nouveau `pointer.ts` ou `system.ts`), `os.ts`, `win/index.ts` (`call("pointer", {...})`), Mac
`mac/pointer.ts` (JXA résident), `fake-os.ts`, tests `test/pointer.test.ts` + `test/pointer-api.test.ts`, contrôle
sanity « pointeur » (déplacement de 0,0 et clic non : seulement `move {dx:0,dy:0}` → 200).

### Task 2 : pilote Windows — opération `pointer`
`Native.Pointer.cs` (`SendInput` move relatif / boutons / molette verticale et horizontale), `Native.cs` dispatch,
recompilation, vérification manuelle (le pointeur bouge, clic, molette), Defender.

### Task 3 : tablette — envoi et gestes (logique pure + tests)
`net/PointerChannel.kt` (socket UDP, `seq`, regroupement 16 ms, secours HTTP si l'envoi lève), `ui/pointer/PadGestures.kt`
(reconnaissance pure : déplacement, tape 1/2 doigts, défilement 2 doigts, double tape + glisser, accélération),
`SystemApi`/API dédiée pour les routes HTTP ; tests JVM.

### Task 4 : tablette — onglet « Pavé » du Deck
Vue `PadView` (surface + boutons Clic gauche / Clic droit), onglet dans `DeckFragment` (après « Ouvertes »), écran
allumé pendant l'affichage, Cadran, chaînes. Mesure de latence (journal de débogage côté tablette et compagnon, horodatage).
