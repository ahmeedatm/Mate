# GitLab dans le Deck — plan de développement

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal :** un onglet « GitLab » dans le Deck : mes MR et les MR à relire, avec pipeline, approbations, état de fusion ; ouvrir une MR sur l'ordinateur ; fusionner une MR prête (appui maintenu).
**Spec :** [docs/superpowers/specs/2026-10-29-gitlab-design.md](../specs/2026-10-29-gitlab-design.md)
**Carte :** COMP-37 · branche `plugin-gitlab`

## Global Constraints

- Les agents ne commitent pas, n'indexent pas, ne poussent pas. Aucune MR GitLab créée, aucune MR réelle fusionnée pendant les essais (seulement contre un faux GitLab local).
- Jeton `GITLAB_TOKEN` : seulement dans `backend/.env` (jamais dans l'APK, un intent, un journal, une réponse HTTP, un message d'erreur). Pas de `glab` (absent sous Windows, variable du shell invisible du lancement automatique).
- Contrat HTTP (derrière le jeton d'appairage, Mac et Windows ; ailleurs 501) :
  - `GET /gitlab/mrs` → `{ mine: Mr[], review: Mr[] }`. `Mr` = `{ project, iid, title, draft, author, pipeline, approvals: { given, required, by: string[] }, status, statusLabel, mergeable, sha, updatedAt }`. `pipeline` ∈ `success | running | failed | canceled | none`. `status` = `detailedMergeStatus` en minuscules. `statusLabel` = phrase française. `mergeable` = `status === "mergeable"`. `sha` = `diffHeadSha`. `iid` entier (GitLab le rend en chaîne). Plus récentes en haut (`updatedAt` décroissant).
  - `POST /gitlab/mrs/merge` `{ project, iid, sha }` → `{ ok: true }` ; erreurs en français (voir Task 1).
  - `POST /gitlab/mrs/open` `{ project, iid }` → `{ ok: true }` ; l'URL est reconstruite (`GITLAB_URL/<project>/-/merge_requests/<iid>`) puis passe par `openTarget` (donc `open-guard.ts`), jamais une URL de la tablette.
  - `GET /deck/features` gagne `gitlab: boolean` = `canControl && jeton réglé`.
- Statuts renvoyés à la tablette : jamais 401 (la tablette y lit « appairer à nouveau », `errorText`). Jeton GitLab refusé → 502 avec phrase française. Jeton absent → 503.
- Requête GraphQL de la spec + `diffHeadSha` + `updatedAt` (nécessaire à l'ordre « plus récentes en haut »). `state: opened`, `first: 50` (pas de pagination). `iid` est une chaîne, `detailedMergeStatus` et `headPipeline.status` en MAJUSCULES.
- Fusion : REST `PUT /api/v4/projects/<fullPath encodé>/merge_requests/<iid>/merge` avec `{ sha }`. Cache de lecture 20 s, vidé après une fusion.
- Tablette : relecture toutes les 30 s seulement quand l'onglet est affiché. Fusion = `HoldButton`, actif seulement si `mergeable`. Textes dans `strings.xml`, couleurs `?attr/c_…`, erreurs par `errorText(e)`. Pas de nouvelle dépendance.
- Vérifs : backend `cd backend && npm run lint && npm run coverage` (seuils de `.c8rc.json` : ne pas les baisser) ; Android `./gradlew ktlintCheck testDebugUnitTest lintDebug assembleDebug` (avant : `ktlintFormat` et `npm run format`).

Signatures :
```ts
export type Pipeline = "success" | "running" | "failed" | "canceled" | "none";
export type Mr = { project: string; iid: number; title: string; draft: boolean; author: string; pipeline: Pipeline;
  approvals: { given: number; required: number; by: string[] }; status: string; statusLabel: string;
  mergeable: boolean; sha: string; updatedAt: string };
export class GitLabError extends Error { statusCode: number }   // message français, jamais le jeton ni le corps de GitLab
export const gitlabConfigured: () => boolean                    // GITLAB_TOKEN non vide
export function listMrs(): Promise<{ mine: Mr[]; review: Mr[] }>  // cache 20 s, une lecture à la fois
export function mergeMr(project: string, iid: number, sha: string): Promise<void>  // vide le cache
export function mrUrl(project: string, iid: number): string       // GITLAB_URL (défaut https://gitlab.unowhy.dev, sans « / » final)
export const statusLabel: (status: string) => string             // table + repli « Pas fusionnable pour l'instant »
export const pipelineOf: (status: string | null | undefined) => Pipeline
```
Mise en forme : `approvals.given = approvalsRequired - approvalsLeft` borné ≥ 0 (champs absents = 0) ; `by` = `approvedBy.nodes[].name` ; `author` = `author.name` ; `iid` = `Number`. En-tête `PRIVATE-TOKEN` (à confirmer par un vrai appel en lecture avec `$GITLAB_TOKEN`, sinon `Authorization: Bearer`).

Libellés (`statusLabel`) : à valider sur l'instance par introspection en lecture (`__type(name: "DetailedMergeStatus") { enumValues { name } }`) avant d'écrire la table. Base : `MERGEABLE` Prête à fusionner · `NOT_APPROVED` Approbation manquante · `CI_STILL_RUNNING` Pipeline en cours · `CI_MUST_PASS` Pipeline à faire passer · `DRAFT_STATUS` Brouillon · `CONFLICT` Conflit à résoudre · `NEED_REBASE` Rebase nécessaire · `DISCUSSIONS_NOT_RESOLVED` Discussions à résoudre · `BLOCKED_STATUS` Bloquée par une autre MR · `UNCHECKED`/`CHECKING` Vérification en cours · `REQUESTED_CHANGES` Modifications demandées. Pipeline : `SUCCESS`/`SUCCESS_WITH_WARNINGS` → success ; `FAILED` → failed ; `CANCELED`/`CANCELING` → canceled ; `RUNNING`, `PENDING`, `CREATED`, `PREPARING`, `WAITING_FOR_RESOURCE`, `SCHEDULED` → running ; null, `MANUAL`, `SKIPPED`, inconnu → none.

Erreurs (jamais 401 vers la tablette) :

| Cas | statusCode | Message |
|---|---|---|
| jeton absent | 503 | GitLab n'est pas réglé sur l'ordinateur (GITLAB_TOKEN dans .env) |
| GitLab 401/403 en lecture | 502 | Le jeton GitLab de l'ordinateur est refusé |
| réseau, délai (15 s), `errors` GraphQL, HTTP ≥ 500 | 502 | GitLab ne répond pas |
| fusion 405 | 409 | Cette MR ne peut pas être fusionnée pour l'instant |
| fusion 409 (sha) | 409 | La MR a changé depuis l'affichage : relis la liste |
| fusion 401/403 | 502 | Le jeton GitLab n'a pas le droit de fusionner |
| fusion 404 | 404 | MR introuvable |
| fusion 422 | 409 | La branche ne peut pas être fusionnée |

}
