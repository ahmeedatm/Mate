# Hackathon Unowhy : compagnon de bureau sur tablette 4.2

### Le projet
Unowhy a des tablettes **Unowhy 4.2** (tablettes SQOOL) en stock, sous Android 8 à 11 selon les lots. **On cible Android 10** (celle d'Eliot, et l'image sans surcouche demandée). Un hackathon interne doit leur trouver une seconde vie. Elles sont peu puissantes : pas question de faire tourner de l'IA en local ni des applis lourdes.

### L'idée de départ (Eliot)
Un **compagnon de bureau** : la tablette posée sur le bureau, avec plusieurs modes :
- **Mode assistant IA** : on parle (ou on écrit), l'IA répond à l'écran et à la voix.
- **Mode "Steam Deck" / sons** : interface média et ambiance (sons d'ambiance, contrôle audio, retours sonores, Bluetooth vers une enceinte). Interprétation à confirmer avec Eliot.
- **Autres usages d'assistant** : timer / Pomodoro, agenda, météo, notifications, etc.

### Contraintes techniques connues
- Cible : **Android 10 (API 29)**, tests sur l'émulateur `companion_api29` puis la vraie tablette. `minSdk 24` est gardé (ne coûte rien, laisse tourner les lots en Android 8). Les `<queries>` du manifeste restent pour Android 11+.
- D'après le support SQOOL (à confirmer par adb) : MediaTek MT8167 4 cœurs 1,3 GHz, 2 ou 3 Go de RAM, écran 10,1" 1280×800. Numéro de série commençant par 7733 = V4.2.
- Pas d'IA locale. Toute l'intelligence est dans le cloud (speech-to-text, LLM, text-to-speech). La tablette ne fait que l'interface : micro, écran, haut-parleur.
- Aucun secret (clé API) ne doit être stocké sur la tablette : passer par un petit backend proxy.

### Architecture "client léger + cloud"
1. La tablette capte la voix (bouton ou mot de réveil léger type Porcupine).
2. L'audio part vers un service de speech-to-text.
3. La transcription part vers une API LLM (ex. Claude).
4. La réponse est lue via synthèse vocale sur le haut-parleur.

Le mode ambiance/sons et le mode timer sont très légers (lecture audio, Bluetooth, UI simple).

### Décisions techniques proposées (à valider)
- **Appli Android native en Kotlin**, `minSdk 24`, une seule Activity plein écran (mode kiosque / lanceur), architecture simple par "modes" (écrans).
- Dépendances minimales (APK léger, compat API 24).
- **Backend proxy** léger qui détient les clés API et expose 2 endpoints (`/transcribe` et `/chat`). Clés dans `.env` (ignoré par git).
- Phase 1 : chat texte + bouton micro. Phase 2 : mot de réveil + synthèse vocale. Phase 3 : modes ambiance et timer.
- Test sur **tablette réelle** via adb dès le premier jour (l'émulateur ne reflète pas les perfs).

### Conventions du code
- **Vision (Eliot)** : la tablette est un compagnon de l'ordinateur (Mac ou PC Windows ; bureau le jour, maison le soir : tâches, rappels, fenêtres/écrans et macros pour jouer). Deck façon Stream Deck (lancer/piloter les applis, son, micro), documents ouverts à côté des conversations, agenda affiché, caméra (photo → Mac), raccourcis. Tablette lente : tout doit rester léger ; elle passera en mode kiosque (docs/kiosque.md).
- **Android** (`app/`) : Kotlin, vues XML (pas de Compose), une Activity (`MainActivity`) + un Fragment par mode (Accueil, Deck, Assistant, Depuis l'ordi — « Ordi » dans la barre, anciens Docs puis Partage, `DocsFragment`, `Mode.DOCS` : écran de choix Fichiers de l'ordi / Page de l'ordi comme Caméra, puis la liste —, Focus, Caméra, Réglages) + `DocumentPanel` à droite ; barre latérale : `TabletStatusView` (heure, WiFi, batterie : la barre d'état est masquée en kiosque), bandeau batterie faible ; `device/Tablet` (batterie, signal, IP) et `device/Screen` (luminosité par la fenêtre, atténuée 22 h – 7 h, un toucher la rallume), carte Tablette dans Réglages ; `WelcomeView` par-dessus tout tant qu'aucun ordinateur n'est appairé (WiFi, `BuildConfig.INSTALL_URL`, recherche ; sans ordinateur, Deck/Assistant/Partage/Caméra ne sont pas créés et `view_connect` les remplace, l'Accueil garde heure et Focus) (documents et page web de l'ordinateur ; en grand dans Partage, à côté ailleurs, `setExpanded`). L'Accueil est un écran à widgets personnalisable (package `ui/home/` : `WidgetModel` = grille 4 × 4, tailles S/M/L/T/W/XL, 11 widgets, modèles Travail / Maison-Jeu / Veille, jusqu'à 3 pages, disposition propre à la tablette dans les préférences `home_layout` ; `WidgetGrid` = placement, appui long → mode Modifier (✕, taille, ⚙, glisser, + sur une case vide), balayage entre pages, 2 colonnes qui défilent quand le panneau document est ouvert ; `HomeWidgets`/`CalendarWidgets`/`KeysWidget`/`WeatherWidget` ; météo Open-Meteo appelée par la tablette, sans clé ; sans ordinateur, `ConnectWidget` remplace les widgets qui en ont besoin). Les widgets regroupent agenda (aujourd'hui + 7 jours, groupés par jour ; agenda personnel noté depuis la tablette avec + / `EventDialog`, `backend/src/events.ts`, `.data/events.json`, rappel parlé), tâches (`TasksCard`), Eau (`WaterCard` + `focus/Water`, sur la tablette seulement, rappel « Pense à boire » 9 h – 20 h chaque minute depuis `MainActivity`), mini-Focus et son du Mac (`MacAudioView`, partagé avec le Deck) ; l'ancien mode `tasks` envoyé par le Mac mène à l'Accueil. Style : 4 thèmes (Nuit, Clair, Néon, Chaud ; `ui/Themes.kt`, choix dans Réglages, `recreate()`) ; couleurs = attributs `?attr/c_…` (`attrs.xml`, valeurs dans `palettes.xml`), dans le code `themeColor(context, R.attr.c_…)`, jamais de couleur en dur ; teintes par fonction `c_hue_*` et animations légères dans `ui/Look.kt` (titres de carte = `TitleView` : icône dans une pastille de la teinte de la fonction ; initiales de tuiles colorées par marque ; appui = `@animator/press`, arrivée des modes `mode_in`, widgets décalés, boucles arrêtées hors écran) ; styles `Card`/`Chip`/`IconButton`/`PrimaryButton` dans `themes.xml`, icônes vectorielles `ic_*` (Material) ; état sélectionné des pastilles et de la barre latérale via `isSelected`. `FocusTimer` et `NoisePlayer` (package `focus/`) sont des singletons : ils survivent aux changements de mode ; l'ambiance suit le chrono (pause = silence, `NoisePlayer.followTimer`), le haut-parleur de Focus la coupe (`muted`) ; pendant la concentration, Ne pas déranger sur l'ordinateur (`MainActivity.followFocusDnd` → `POST /system/dnd`, `backend/src/dnd.ts` ; Windows : interrupteur du centre de notifications par UI Automation dans `helper.ps1`, Mac : raccourcis Apple, `docs/ne-pas-deranger.md`). Dépendances limitées à appcompat, lifecycle-runtime-ktx, coroutines : en ajouter une seulement si c'est indispensable et compatible API 24. HTTP via `HttpURLConnection` + `org.json` (`net/BackendClient.kt`). Erreurs affichées via `errorText(e)` (`ui/Errors.kt`) : jamais de `e.message` brut à l'écran ; côté backend, les erreurs techniques (`technical`, erreurs système, validation) sont remplacées par une phrase dans `setErrorHandler`, nos `throw new Error("…")` en français passent tels quels. Noms historiques `Mac*` (`MacWindow`, `MacAudioView`, `openOnMac`) = l'ordinateur piloté, Mac ou Windows ; les textes affichés disent « ordinateur » (« ordi » sur les boutons courts).
- AGP 9 avec Kotlin intégré : pas de plugin `kotlin-android` à appliquer. Sources dans `src/main/kotlin`.
- Ordinateurs : la tablette garde une liste (`Computers.kt` : id du backend, nom renommable, url, jeton, os) et pilote l'actif (`Prefs.backendUrl/token` en dérivent ; sans ordinateur, `BuildConfig.DEFAULT_BACKEND_URL`). Ajout : recherche UDP sur le WiFi (`net/Discovery.kt`) ou adresse saisie, puis code à 6 chiffres affiché sur l'ordinateur (`ui/ComputerAdder.kt`). `net/Connection.kt` : si l'actif ne répond plus, adresse mise à jour par la recherche ou bascule vers un autre ordinateur qui répond ; `MainActivity.onComputerChanged` recrée tous les écrans et relance le canal. Chaque ordinateur garde ses données (agenda, tâches, deck). HTTP en clair autorisé en debug et en release (`res/xml/network_security_config.xml`) : réseau local, protégé par le jeton d'appairage (HTTPS épinglé à l'appairage = piste production).
- **Backend** (`backend/`) : Node 22, TypeScript exécuté par `tsx`, Fastify. Fournisseurs derrière l'interface `Providers` (`src/providers.ts`), choisis par `MODE=mock|live`. Pilotage par système derrière `src/os.ts` (seul point d'entrée : `launchApp`, `openTarget`, `sendKeys`, fenêtres, son…) : `src/mac/` (osascript/JXA) et `src/win/` (`helper.ts` garde un Windows PowerShell 5.1 résident, lancé sur une copie de `helper.ps1`/`native.cs` dans `%LOCALAPPDATA%\UnowhyCompanion\helper` pour ne pas verrouiller les originaux ; `native.cs` : C# 5 seulement ; testé sur le PC d'Eliot). Types d'écrans/fenêtres partagés dans `src/screens.ts`. Lancement automatique : `scripts/service.ts` (`npm run service:install|stop|start|status|uninstall` ; LaunchAgent sur Mac, clé Run + `scripts/run-windows.ps1` sur Windows), installeurs à double-cliquer à la racine ; paquets clients avec node embarqué par `npm run package` (`scripts/package.ts`, esbuild → `dist/server.mjs`, zips dans `dist/` ; fichiers lus à l'exécution toujours trouvés depuis `backendRoot` de `config.ts`, pas depuis le dossier du module).

Les actions du deck sont définies uniquement dans `backend/config/deck.json` et dans les touches perso (`backend/.data/keys.json`, page Perso, `src/perso.ts` ; une touche = liste d'étapes, plusieurs = macro), toutes exécutées par `runAction` (`src/deck.ts`) ; deck de départ `config/deck.example.json` (Mac) ou `deck.example.windows.json`, filtré aux applis installées. ### Environnement local (Mac, Apple Silicon)
- Projet isolé dans `~/side-projects/unowhy-companion`, séparé des repos du boulot.
- SDK Android : `~/Library/Android/sdk` (à référencer via `local.properties`, car `ANDROID_HOME` dans `~/.zshrc` pointe vers le cask platform-tools).
- JDK 21, Node 22, adb 1.0.41.
