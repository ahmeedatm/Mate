# Hackathon Unowhy : compagnon de bureau sur tablette 4.2

### Le projet
Unowhy a des tablettes **Unowhy 4.2** (tablettes SQOOL) en stock, sous Android 8 à 11 selon les lots. **On cible Android 10** (celle d'Eliot, et l'image sans surcouche demandée). Un hackathon interne doit leur trouver une seconde vie. Elles sont peu puissantes : pas d'applis lourdes. Pas d'IA : l'Assistant IA a été abandonné le 26/10/2026.

### L'idée de départ (Eliot)
Un **compagnon de bureau** : la tablette posée sur le bureau, avec plusieurs modes :
- **Mode "Steam Deck" / sons** : interface média et ambiance (sons d'ambiance, contrôle audio, retours sonores, Bluetooth vers une enceinte). Interprétation à confirmer avec Eliot.
- **Autres usages de bureau** : timer / Pomodoro, agenda, météo, notifications, etc.

### Contraintes techniques connues
- Cible : **Android 10 (API 29)**, tests sur l'émulateur `companion_api29` puis la vraie tablette. `minSdk 24` est gardé (ne coûte rien, laisse tourner les lots en Android 8). Les `<queries>` du manifeste restent pour Android 11+.
- **Seul matériel cible** : spec relevée par adb dans `docs/tablette-4.2.md` (MT8167 4 × Cortex-A35 1,3 GHz, 2 Go de RAM, tas de 128 Mo, GPU PowerVR GE8300, écran 1280×800 à 55 Hz soit 18,2 ms par image, WebView 81, pas de vibreur). Toute décision technique se vérifie contre elle. Numéro de série commençant par 7733 = V4.2.
- Pas d'IA, ni locale ni cloud (Assistant IA retiré le 26/10/2026). La tablette est une interface : micro (commande vocale par la reconnaissance Android), écran, haut-parleur.
- Aucun secret (clé API) ne doit être stocké sur la tablette. Seule exception (27/10/2026) : le deploy token « tablettes-mises-a-jour », en lecture seule du registre de paquets du projet (`read_package_registry`), injecté par la CI dans l'APK release pour lire les mises à jour (variable `UPDATE_DEPLOY_TOKEN`).

### Architecture "client léger"
La tablette est l'interface ; le backend sur l'ordinateur pilote l'ordinateur. Aucune IA (Assistant IA retiré le 26/10/2026).

### Points à vérifier avant de coder (bloquants possibles)

Le MDM SQOOL (`com.hisqool.devicemanager`) est une appli installée dans `/data`, **profile owner** (pas device owner) ; seule restriction : `no_add_user`. adb et l'installation d'APK par adb fonctionnent déjà. Procédure : `docs/kiosque.md`. L'appli n'a pas besoin des services Google ; elle utilise le WebView (« Page de l'ordi »), qu'elle met à jour elle-même (carte Mises à jour).

### Règles de travail
- Une question à la fois si une info manque, plutôt que deviner.
- Expliquer les choix en 1-2 phrases.
- Ne rien commit sans demande explicite.
- `main` protégée : tout passe par une branche et une MR, fusionnée seulement avec le pipeline vert (`.gitlab-ci.yml` : format prettier + typecheck + tests d'intégration backend sous seuil de couverture (`backend/.c8rc.json`), tests Playwright des pages web du backend, ktlint + tests JVM + lint + APK Android ; `npm run format` et `./gradlew ktlintFormat` avant de pousser ; voir `docs/developpement.md`). Nouveau comportement backend = un test dans `backend/test/` ; page web servie par le backend = un test dans `backend/e2e/` ; logique pure Android = un test dans `app/src/test/`. Release : tag `vX.Y.Z` sur `main` → paquets, APK signé (clé en variables CI protégées), release GitLab ; `versionName`/`versionCode` suivent le tag (`-PappVersion`) ; `npm run updates:add` alimente le « serveur Unowhy » (docs/developpement.md, section Release).
- Essai de l'appli tablette depuis une MR, sans fusion ni tag : branche protégée `essai/mr-<iid>`, job manuel `essai-android` (version `X.Y.Z-essai.N`, code entre deux tags : versionCode = (X × 10000 + Y × 100 + Z) × 1000), paquet `companion-updates/essai` (jamais `latest`), puis `npm run updates:essai` sur l'ordinateur (docs/developpement.md, section Release). L'essai est une autre appli, `com.unowhy.companion.essai` « Companion essai » (`-essai.N` → `applicationIdSuffix`, `BuildConfig.TRIAL`), installée à côté de la stable, qui reste device owner : la stable l'installe (ligne à part dans Mises à jour), l'autorise en lock task et l'ouvre (« Ouvrir l'essai ») ; l'essai reprend ses ordinateurs par `trial/ComputersProvider` (permission signature, jamais de jeton dans un intent ou un fichier) et rend la main (« Revenir à la stable ») ; package `trial/`.
- Installation, `backend/src/mac/` ou `service.ts` touchés : le job `install-mac` (runner Mac du développeur, instance de test isolée de son vrai compagnon, `COMPANION_LABEL`/`COMPANION_HEADLESS`, `backend/qa/install-mac.sh`) bloque la MR ; ailleurs, il est manuel (docs/developpement.md, section CI).
- CI ciblée par zone (`rules:changes` en MR, tout sur main et les tags ; pas de nightly) ; `backend/qa/sanity.ts` = un contrôle par feature contre un compagnon réel, lancé par `install-windows` (PC Windows de QA, runner `local-runner`, instance de test isolée elle aussi, nettoyée en after_script) ; nouvelle feature backend = un contrôle dans la sanity ; voir docs/developpement.md, section Branches, MR et CI.

### Conventions du code
- **Vision (Eliot)** : la tablette est un compagnon de l'ordinateur (Mac ou PC Windows ; bureau le jour, maison le soir : tâches, rappels, fenêtres/écrans et macros pour jouer). Deck façon Stream Deck (lancer/piloter les applis, son, micro), documents ouverts à côté des conversations, agenda affiché, caméra (photo → Mac), raccourcis. Tablette lente : tout doit rester léger ; elle passera en mode kiosque (docs/kiosque.md).
- **Android** (`app/`) : Kotlin, vues XML (pas de Compose), une Activity (`MainActivity`) + un Fragment par mode (Accueil, Deck, Depuis l'ordi — « Ordi » dans la barre, anciens Docs puis Partage, `FromComputerFragment`, `Mode.COMPUTER` (clé `docs` gardée pour l'ordinateur et l'état sauvegardé) : écran de choix Fichiers de l'ordi / Page de l'ordi comme Caméra, puis la liste —, Focus, Caméra, Réglages) + `DocumentPanel` à droite ; barre latérale : `TabletStatusView` (heure, WiFi, batterie : la barre d'état est masquée en kiosque), bandeau batterie faible ; `device/Tablet` (batterie, signal, IP) et `device/Screen` (luminosité par la fenêtre, atténuée 22 h – 7 h, un toucher la rallume), carte Tablette dans Réglages ; `WelcomeView` par-dessus tout tant qu'aucun ordinateur n'est appairé (WiFi, `BuildConfig.INSTALL_URL`, recherche ; sans ordinateur, Deck/Assistant/Partage/Caméra ne sont pas créés et `view_connect` les remplace, l'Accueil garde heure et Focus) (documents et page web de l'ordinateur ; en grand dans Partage, à côté ailleurs, `setExpanded`). L'Accueil, appelé « Profils » depuis le 28/10 (`Mode.HOME`, clé `home` gardée), est un écran à widgets personnalisable : chaque page de la grille est un profil nommé, sans limite de nombre (package `ui/home/` : `WidgetModel` = grille 4 × 4, tailles S/M/L/T/W/XL, 15 widgets, modèles Bureau / Gamer / Veille, `HomeLayout` porte `names` et `gameProfile`, JSON v2 (une v1 se relit, les noms null deviennent « Bureau » et « Profil N », enregistrés au chargement), disposition propre à la tablette dans les préférences `home_layout_cadran` ; barre de profil en haut de l'écran (flèches, nom, pastilles décoratives), toucher le nom ouvre `ProfilesDialog` : créer vide ou depuis un modèle, renommer, monter, supprimer (sauf le dernier), marquer le profil de jeu (pour la détection de jeu, lot 4) ; seuls les widgets du profil affiché se chargent ; `WidgetGrid` = placement, appui long → mode Modifier (✕, taille, ⚙, glisser, + sur une case vide), balayage entre profils, 2 colonnes qui défilent quand le panneau document est ouvert ; `HomeWidgets`/`CalendarWidgets`/`KeysWidget`/`WeatherWidget` ; météo Open-Meteo appelée par la tablette, sans clé ; sans ordinateur, `ConnectWidget` remplace les widgets qui en ont besoin). Les widgets regroupent agenda (aujourd'hui + 7 jours, groupés par jour ; agenda personnel noté depuis la tablette avec + / `EventDialog`, `backend/src/events.ts`, `.data/events.json`, rappel parlé), tâches (`TasksCard`), Eau (`WaterCard` + `focus/Water`, sur la tablette seulement, rappel « Pense à boire » 9 h – 20 h vérifié chaque minute, `ui/TabletAlerts` : coupé par défaut, cloche du widget Eau, seulement si ce widget est sur un profil, `HomeLayout.has`), mini-Focus et son de l'ordinateur (`ComputerAudioView`, partagé avec le Deck) ; l'ancien mode `tasks` envoyé par le Mac mène à l'Accueil. Style : 3 thèmes, Cadran, Cadran nuit et Rétro (`ui/Themes.kt`, choix dans Réglages, `recreate()` ; un ancien choix Nuit, Clair, Néon ou Chaud retombe sur Cadran). Rétro = Cadran habillé années 70 (palette `Palette.Retro`, titres et grands chiffres en Abril Fatface, textes en Nunito), grain par-dessus l'écran (`ui/Grain.kt`, `c_grain_*`) et tubes où coule un liquide derrière l'Accueil, à droite (`ui/home/FlowBandView`, `c_flow*`, dégradés seulement ; voilés derrière les widgets sans fond, `WidgetType.bare` ; widgets de l'Accueil translucides, `c_home_card_bg` ; textes foncés de l'Accueil détourés d'un halo crème, `Look.haloTexts` ; titres de carte plus grands, `c_title_size`) ; polices par rôle : `c_font_regular`, `c_font_medium`, `c_font_light`, `c_font_title` (titres), `c_font_display` (heure, chrono), jamais `@font/` en dur. Cadran = la DA de `docs/ui-ux/da` : attributs de thème propres (`c_cadran`, `c_card_bg`, `c_primary`, `c_graphic`, polices Outfit `c_font_*`), Accueil à lignes inégales (`RowProfile`, taille V, disposition `home_layout_cadran`), héros (`HeroWidget`, chiffres qui basculent `RollingText`, `MinuteClock` calé sur la minute pleine), ligne du jour (`DayLineView`), menu caché à la place de la barre latérale (`MenuPanel`, `DrawerGesture`), ordinateur injoignable dit une fois (`LinkWatch`) ; ressorts M3 dans `Look.kt` (`androidx.dynamicanimation`). Le code des anciens thèmes (barre latérale, Accueil à 4 lignes égales, `c_cadran` faux) n'est plus atteint : à retirer ; couleurs = attributs `?attr/c_…` (`attrs.xml`, valeurs dans `palettes.xml`), dans le code `themeColor(context, R.attr.c_…)`, jamais de couleur en dur ; teintes par fonction `c_hue_*` et animations légères dans `ui/Look.kt` (titres de carte = `TitleView` : icône dans une pastille de la teinte de la fonction ; initiales de tuiles colorées par marque ; appui = `@animator/press`, arrivée des modes `mode_in`, widgets décalés, boucles arrêtées hors écran) ; styles `Card`/`Chip`/`IconButton`/`PrimaryButton` dans `themes.xml`, icônes vectorielles `ic_*` (Material) ; état sélectionné des pastilles et de la barre latérale via `isSelected`. `FocusTimer` et `NoisePlayer` (package `focus/`) sont des singletons : ils survivent aux changements de mode ; l'ambiance suit le chrono (pause = silence, `NoisePlayer.followTimer`), le haut-parleur de Focus la coupe (`muted`) ; pendant la concentration, Ne pas déranger sur l'ordinateur (`focus/FocusDnd`, suivi par `MainActivity.followFocusDnd` → `POST /system/dnd`, `backend/src/dnd.ts` ; Windows : interrupteur du centre de notifications par UI Automation dans `helper.ps1`, Mac : Centre de contrôle par Accessibilité, éléments trouvés par identifiant, `src/mac/dnd.ts`). Dépendances limitées à appcompat, lifecycle-runtime-ktx, coroutines : en ajouter une seulement si c'est indispensable et compatible API 24. HTTP via `HttpURLConnection` + `org.json` : `net/BackendClient.kt` = point d'accès, un client par domaine (`client.deck`, `.windows`, `.system`, `.docs`, `.calendar`, `.tasks`, `.camera`, `.updates`, `.tablet`, `.pairing` ; fichiers `net/*Api.kt`, modèles à côté), plomberie et `HttpException` dans `net/Http.kt`. Erreurs affichées via `errorText(e)` (`ui/Errors.kt`) : jamais de `e.message` brut à l'écran ; côté backend, les erreurs techniques (`technical`, erreurs système, validation) sont remplacées par une phrase dans `setErrorHandler`, nos `throw new Error("…")` en français passent tels quels. Noms `Computer*` (`ComputerWindow`, `ComputerAudioView`, `openOnComputer`) = l'ordinateur piloté, Mac ou Windows ; `Mac` seulement pour ce qui est propre au Mac (`backend/src/mac/`, réglage Accessibilité) ; les textes affichés disent « ordinateur » (« ordi » sur les boutons courts).
- AGP 9 avec Kotlin intégré : pas de plugin `kotlin-android` à appliquer. Sources dans `src/main/kotlin`.
- Ordinateurs : la tablette garde une liste (`Computers.kt` : id du backend, nom renommable, url, jeton, os) et pilote l'actif (`Prefs.backendUrl/token` en dérivent ; sans ordinateur, `BuildConfig.DEFAULT_BACKEND_URL`).
